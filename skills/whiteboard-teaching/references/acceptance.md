# 绘制流程与质量验收

按任务范围执行本流程。它是内容与工具工作规范，不是新增 MCP 参数或自动审美评分器。

## 根据修改范围决定规划深度

| 请求 | 规划与执行 |
| --- | --- |
| 复杂新图、完整机制或跨模块重组 | 内容方案、图形方案、核心预览、局部展开、整体复验与保存 |
| 短流程、单一概念或少量节点 | 简述真实关系和结构，预览与局部验收；不强加多个详解 |
| 改字、字号、颜色或指定位置 | 回读目标及邻居，明确小范围改动，预览、提交、核对保护；不重画主结构 |
| 已有图逻辑有误 | 先说明错误关系及正确层级，再改相关区域；不能只做视觉整理 |

用户已授权的普通规划与绘制步骤连续推进。涉及未确定事实或范围才澄清，不把每份规划变成新的审批门槛。

## 分步工作流与产出

| 步骤 | 产出 | 下一步前核对 |
| --- | --- | --- |
| 内容选择与逻辑拆解 | 共同骨架、差异归属、整体模块、内容层级及资料边界 | 核心能独立说明目标关系，共性没有冒充共同架构 |
| 有详细规格时的映射 | 原编号、父级/解释对象、摘要与展开位置；关系展示层级与必要标签 | 明确内容均有去处，摘要不丢关键机制或条件；不自动逐项变成主图框线 |
| 图形与空间规划 | 核心视图、各部分表达方式及理由、邻近对照和详解、连接与样式 | 表达符合真实关系，核心与详解的空间职责分开 |
| 核心预览 | 核心及理解它所需的内部步骤、连接和条件 | 常用窗口能辨认整体，不需滚过长篇详解才能接上主线 |
| 局部展开 | 就近对照、小机制图、公式与必要说明 | 比较同口径，未知项明确，深度足够且归属易找 |
| 整体复验与保存 | 核心、全图、必要局部的检查与保存回读 | 补充后核心仍完整，局部可读，身份与保存正确 |

这些产出可用简洁段落或表格，不要求每步单独建文件。多批次、长任务或需要续作时按项目约定留存内容方案、图形方案、已完成批次与待办；恢复时重新读取白板身份和版本。它是 Skill 的执行方法，不是已存在的 MCP 工作流引擎。简短任务合并步骤，局部修改只检查相关对象及邻居。

## 阶段一 核对资料与目标

核对任务、资料版本、事实边界和用户阅读目的；引用原资料而非仅凭旧笔记。明确是生成新文稿、维护旧图还是局部调整，并保护用户其他内容。

status 确认目标标题与编辑页，read 取得最新身份、版本、完整边界、分区与相关对象。不同文稿或会话不复用身份。缓存工具、离线、未保存、正在输入或恢复问题按 tools 处理。

## 阶段二 逻辑规划与检查

按 authoring 写出主要关系、共同职责、整体组件、通用对象、差异归属与必要附属内容，检查常见偏离：

1. 先摆多个方案，却没有共同问题、比较层级与共同上级。
2. 只写内部算子，完整组件名称与边界消失。
3. 主图输入输出完全依赖某个业务实例，缺少通用对象定义。
4. 默认把训练、校准、公式或反馈加入资料并不涉及的过程。
5. 把时间先后、组成、替代、解释归属误画成共同执行或因果链。
6. 按每个方案重复讲完整原理，未把共性、局部差异、机制与补充材料分层；或拆开跨职责方案后丢失整体耦合。
7. 详细规格直接铺成主图，缺少整体机制总结；或者为减少内容静默遗漏明确要求，而没有保留摘要与展开映射。

出现这些问题先修内容方案；不要用调整坐标掩盖逻辑。共同功能不等于共同内部实现，未知部分保留边界。

## 阶段三 图形规划与检查

按 layout 为每部分选择结构与理由，明确核心范围、阅读路线、必要分组、连接、字号层级、色彩及附近解释空间。方向和整体轮廓由内容关系与常用窗口决定，允许局部不同方向；局部修改保留已有结构。

容器表达真实边界，标题和空间分组也可表达归属；分支采用真实条件，比较组按同级维度排列，必要单元包含小图。主次依靠核心集中、层级、位置、字号与样式组合，详解可以较小但聚焦后清楚。文字与边框比例根据测量确定，保留走线通道。

绘制前核对：核心是否完整可辨且包含必要内部关系；每处对照或详解是否有清楚归属与阅读位置；箭头是否连接真实参与传递的对象。结构紧凑不等于逻辑正确，长引导线不等于详解易找，外框与方向都不是独立的通过条件。

同时检查子框是否按内容测量、并列项是否选择合适方向。父框不因宽度已定就让所有子框拉满；长解释可放纵排节点旁，不要求同级项都横排。关键路径与局部计算依赖分层，线中文字有必要作用，阅读主线不需要逐条辨认重复字段或穿过大量旁支。

## 阶段四 分批预览与保存

先画可独立讲解的核心，包括必要内部步骤、嵌套和连接，预览核心名称、机制与阅读路径后再补详解；核心可能分多批，不是只检查空外框。随后就近加入局部对照、机制小图、公式和说明，不将全部详解塞入主链。每批不超过工具上限，alias 在本批内使用，跨批回读真实 ID。公式渲染可独立成批，分式和矩阵按实际高度留空间。补充后重新查看核心，发现被撑散或遮住时调整对应区域。

每批 preview 之后查看真实候选 PNG 与报告。尚未绘制的区域可以记录待补，不把阶段性骨架当完成；已经出现的溢出、穿越、错接或资料错误必须处理。长画布按区域检查，不能只看1600像素全图就判断所有小字清楚。

提交使用同一内容与 requestId，携带可选 previewId，移除预览顶层 regionId/elementIds/includeChildren；身份、版本或依赖选区变化时重读并预览。候选短期缓存在内存，不写入白板版本、不增加撤销历史，草稿同步行为另行区分。提交后用完整同版本的 changes/idMap 核对内容、真实 ID、公式源码和版本；信息不足时回读。

超时查询原 boardId 与 requestId 的回执，不能更换 ID 重复执行。applied=false 仍可能已保存。锁定或不支持对象保持原样；工具不足不能通过清空或重建用户文稿补偿。

## 阶段五 四类验收

| 类别 | 通过依据 | 不通过时 |
| --- | --- | --- |
| 内容与逻辑 | 资料支持、共同骨架、整体名、通用对象、层级与关系正确；对照同口径，跨职责方案完整，深度符合目标 | 回到内容方案，改具体关系与取舍 |
| 视觉与讲解 | 核心在常用窗口完整可辨，暂不阅读外围详解仍能讲清机制；局部说明易找且可读，补充后核心仍清楚，配色稳定 | 回到空间规划，就近重排、调整字号层级或深入区并核对连接 |
| 几何与渲染 | 实际字号、比例、换行、边中点、路线、遮挡与公式符合要求 | 按图元和邻居修正，再实际预览 |
| 操作与保存 | 正确身份与版本、候选未保存、提交回读一致，原内容和公式源码受保护 | 停止错误写入，核对连接、回执与保存状态 |

几何验证不能证明内容、主次或语义正确。查看核心、全图及必要局部，不以单个成功请求代替实际阅读。核心视图不自动包含全部外围子详解，按 tools 选择成员 ID。核对隐藏外围内容后核心仍完整、方案比较有共同职责、重要条件未被藏入小字；再检查关键节点与对应说明是否可同屏阅读。长篇或共享深入区有清楚定位与摘要即可，不要求每个推导都挤在节点旁。最小检查覆盖本次实际修改与邻居；批量模型实验、跨主题演练、撤销重做或重启不作为每次绘图的默认步骤。

## 验收记录格式

本轮快速阅读自检可围绕四个问题：核心是否先讲清整体且包含必要机制；关键路径（含跨区域必要交接）是否容易追踪；线中文字是否补充必要信息；子框是否被无理由拉满。采用“核心机制＋周围详解”时，在已有全图与局部检查中核对：独立附图是否小一级而聚焦后仍可读；虚线能否对应具体解释对象；实线是否表达真实交接与反馈；正文和导航是否混入了无需展示的规划编号。无需为这几项增加独立审批、测试阶段或固定缩放指标。复杂任务另核对原规格到摘要/详解的覆盖，减少显式框线不等于删掉要求。检查深度仍以用户范围为准，不自动增加批量测试。

| 区域或图元 | 具体要求 | 实际证据 | 状态 | 修正及复验 |
| --- | --- | --- | --- | --- |
| 真实名称或 ID | 主线、归属、字号、公式等 | PNG、回读、源码或报告 | 通过、需修正、未验证 | 说明改了什么和检查范围 |

复杂任务按需要记录标题、boardId、版本、已检查视图、事实资料和剩余问题，短任务用简短交付说明即可。脚本或项目 SDK 检查与宿主直接调用分别说明，不互相冒充。若用户负责最终体验测试，说明已完成的自检和未做的行为测试，不宣称美观或泛化已验证。示例和测试输入不成为通用内容模板。

## 修正与结束

每轮针对失败原因与邻居：共同骨架错误回到内容拆解，比较层级错误改对照方案，核心被撑散改空间分配，字号、公式或连线问题局部修正。重复采用同一方案无改善时更换表达或说明具体限制，不因固定轮数自动停工，也不盲目重画整板。剩余问题如实记录。

局部修改核对未授权区域的文字、位置、样式、绑定和公式源码。隔离测试需要时验证一次撤销、重做与重新打开后的内容，但不把测试笔画注入正式文稿。

完成时提供有效入口、主要变化、实际验收、未验证与剩余问题。Skill 文件存在、宿主发现、当前工具可见、实际调用成功和成品可读是五项不同证据；用户最终体验验收不提前代替。
