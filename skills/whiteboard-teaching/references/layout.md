# 图形规划与视觉规范

先完成 [authoring.md](authoring.md) 的逻辑规划，再使用下述图形规划，最后安排坐标。沿用轻手写、蓝色基础、大字与紧凑框体。历史稿件条件见 [legacy-laya.md](legacy-laya.md)，新图不加载历史数量、坐标或缩放模板。

## 图形规划的交付

复杂图在绘制前给出主要阅读路线和下表的简洁版本。每个部分写清为什么选这种结构，不只列“画几个框”；规划不默认增加批准步骤。

| 逻辑部分 | 图形结构与理由 | 整体名称和内部层级 | 输入输出或比较对象 | 连线语义与方向 | 附属解释归属 | 颜色和文字角色 |
| --- | --- | --- | --- | --- | --- | --- |
| 按资料命名 | 顺序、组成、比较、分支等 | 保留整体名再展开 | 仅填写资料实际涉及的对象 | 包含不画成执行，替代不画成串联 | 指向具体模块或关系 | 角色一致，不临时随机选色 |

另说明核心视图包含哪些模块与必要内部关系、哪些部分需要外框、解释与对照附属于哪里、入口出口和反馈通道。根据关系与空间选择方向，不预设核心或全图的轮廓。逻辑规划和图形规划是面向读者的可检查方案，不是工具新参数。短流程只需说明结构，局部修改不重做整图规划。

## 关系与结构选择

| 实际关系 | 优先表达 | 检查要点 |
| --- | --- | --- |
| 先后且存在对象传递 | 阅读顺序清楚的步骤与明确箭头，可横向、纵向或局部转向 | 下一步使用什么、为什么相连；转向不造成歧义 |
| 一个整体包含多个组件 | 有名字的容器、共同标题或空间分组，按边界选择 | 不用执行箭头代替包含关系，整体名始终可辨 |
| 同一职责的不同实现 | 对应职责旁的比较表、并列小图或共同标题，按信息选择 | 比较问题与口径明确，替代方案不串成共同执行 |
| 条件分支 | 命名判断点、明确条件、不同结果路径 | 每条路径条件可读；分支与汇合的端口清楚 |
| 返回、调整或循环 | 指向实际返回对象的外围路线 | 不穿过正文，写清返回条件或更新对象 |
| 时间演进 | 时间线与局部展开 | 时间先后不自动当成因果关系 |
| 概念或指标比较 | 同级比较组、对照或映射 | 不强造流程；采用相同比较维度 |
| 机制或公式详解 | 贴近所属部分的子图、公式与说明 | 有明确所属，详解不取代主结构 |

混合主题先选主结构，再在对应位置使用其他结构。多个方案横跨几个职责时，比较组说明其范围，并分别标明差异归属；不能把整方案缩成“一个算子”。

## 形状的用途

| 形状或形式 | 用途 | 约束 |
| --- | --- | --- |
| 命名外框 | 阶段、整体模块、共同职责或比较组 | 每个框有分组意义；不为包住整板增加无职责大框 |
| 矩形或圆润节点 | 操作、组件、对象 | 一个节点一项职责，内部名称不代替外部整体名 |
| 菱形 | 有分支的条件判断 | 不用于所有标题或无条件的处理步骤 |
| 椭圆 | 起点终点、状态或需突出的小对象 | 按语义使用，不为了“形状丰富”随意替换 |
| 独立文字 | 旁注、接口、变量、条件、来源 | 就近附着；主要内容不缩成来源小字 |
| 无框或轻框说明 | 紧邻对象的解释、限制与必要附属小图 | 正文清晰，所属明确；短旁注可不连线，独立附图按下文表达归属 |

工具当前支持的基础形状、端口与样式见 tools。原生框架与 MCP 分区不同，不杜撰圆角半径、字体颜色拆分、泳道或其他不存在的参数。复杂容器优先用 region 声明持久关系。

## 按真实关系安排空间

先安排可独立理解的核心视图，再在所属模块周围留出详解空间。机制讲解可将关键模块集中在中间，以嵌套、分支、汇合和反馈说明内部关系，旁注与小图在周围展开；这是适用的组合方式，不是所有主题的居中模板。流程按实际先后，架构按组成与接口，比较按共同维度，时间线按时间组织。横向与纵向可以组合，转向处保持连接清楚。整图形状、对称性和等高排布不作为目标，用户指定布局时优先沿用。

普通步骤用一个紧凑节点即可，不把每一步都变成“标题 + 外框 + 单个节点”的卡片。只有真实模块、子过程、共同职责或比较边界需要外框；整体名称和成员须可辨，不以节点数量硬性否定有意义的分组。多个方案先有共同职责，可使用共同标题或必要容器；不为了外观给所有步骤做等大卡片。

先按子节点的文字、内部小图和边距测量宽高，再用成员边界与走线范围确定父框。父区的宽度不是每个成员必须占满的行宽；短节点保持紧凑，长说明在相邻独立位置展开。可以为比较统一必要尺寸，但不为填空拉伸所有节点，也不固定框体宽高比；真正需要横向长结构时按内容保留。

“并列”表示同级，不等于横向铺满一行。短项需要直接对照时可横排；每项说明较长时，可纵排节点，右侧逐项放注释、公式或小图；多项可分列或局部分组。选择能同时读清对应关系的方式，不把每个列表变成横排卡片。独立备注不为对齐扩大其节点，核心模块不为包住外围详解被动加宽、加高。

解释可放在所属模块内或周围邻近空白，按内容和通道选择左右、上方或下方；同一高度常便于对照，但不是固定位置。公式与符号说明放在一起，重要局部视图应同时包含解释对象和解释。大篇幅推导或共享内容可有独立深入区，核心保留必要摘要和明确入口；无需将全部详解装进核心容器。

采用“核心机制＋周围详解”时，独立附图通常以浅色、无箭头虚线连接其最直接解释对象，优先从核心模块与附图明确侧边的中点就近连接；不用仅有标题或规划编号代替归属。紧贴节点的一两句旁注、模块内已明确包含的说明可以不连线。共享详解用少量关联和清楚名称说明范围，不向每个内部算子重复拉线。若关联线反而遮挡主线，先调整位置与通道，再选择明确引用等易追踪的方式；不跨越无关内容画长引导线。其他结构不默认增加附图或虚线。

空间不足时先检查重复内容与层级，再重排旁注、对照和必要子过程；可适度调整详解字号、拓展邻近区域或设置深入区，以实际可读为准。不要让大篇幅详解撑长主链，核心仍应完整可辨。核心视图适配常用窗口，不等于整板所有内容必须同屏。局部改字、样式或位置任务保留现有结构，不借通用建议重排整板。

## 局部对照与机制小图

对照围绕一个明确问题展开，标题注明所属职责。少量短差异适合并列小图，多维信息适合表格式排列，复杂实现可用命名子图。根据内容决定方向和数量，不要求所有模型都有同等篇幅。

对照项使用一致维度，可在项内画必要小流程与公式；共同机制在上级讲一次，各项突出差异及条件。真实替代方案之间不加执行箭头。跨职责实现用完整子图和覆盖范围说明，不切断其耦合关系。表格是节点、文字和线组成的视觉表达，不是假设 MCP 支持原生表格参数；轻分隔、共同标题或必要外框均可，不给每个单元重复套框。

## 字号与框体

初始画布字号参考：总标题40–44、核心标题36–40、核心节点32–40、局部标题28–34、详解正文与备注24–30、关键公式28–36、来源20–22。这些是起点，不是下限或固定比例；已有可读字号不自动改动。详解可适度小于核心，但聚焦后正文与公式应舒适可读，约18–24屏幕像素可作参考。核心总览看清主要名称和关系，局部读清细节；实际过小时放大文字或调整区域，重要条件不用来源字号。公式比例保持完整。

采用“核心机制＋周围详解”时，附属标题、正文、节点及公式的视觉尺度可先参考同类核心组件的80%–90%，再依据内容与实际视图调整。这不是整张附图与核心面积之比，也不是对所有已有图执行固定缩放；内容多的附图仍可更大。文字、框体、间距与小图协调调整，不只缩字留下大空框；公式保持比例与源码，来源小字和细小符号不机械按比例继续缩小。局部可读性优先于比例，不为强调主次隐藏关键条件。

用真实字体测量最长标签、行数及公式高度。短节点两侧留白通常各0.4–0.8个字高，上下各0.4–0.6个字高；实际文字与路由需要可调整。外框只保留标题、模块、必要旁注与走线空间，尺寸不要求统一。

小字与大空框同时出现时增大文字占比、收紧框体并重排关联线，不整体等比扩大空白。宽度不足先加宽或按语义换行，不拆小数、变量、上下标或把单个数字挤到下一行；公式保持比例，不能压扁。

## 颜色角色与组件样式

先为本图确定色彩角色，默认使用下面的有限色板。流程可对应输入、处理、结果、条件或边界、正文；架构与比较主题按功能角色映射，不为配色补造输入输出。一个色表示一个稳定含义；模型或方案名称靠文字辨认，不为每个方案强加新色。

| 角色 | 深色文字与节点边框 | 浅填充 | 附属轻框与引导线 |
| --- | --- | --- | --- |
| 输入、接口或基础功能 | `#35639c` | `#edf3fb` | `#9aafcb` |
| 处理或中间机制 | `#6b55a1` | `#f3effa` | `#b2a3ce` |
| 输出或结果 | `#24756a` | `#edf7f4` | `#8bb6ae` |
| 条件、假设与边界 | `#99651f` | `#fff7e8` | `#c9ae83` |
| 普通正文与中性对象 | `#34465e` | `#f3f5f8` | `#b2bdcb` |

浅框与引导色只用于线条或非关键背景，不用于正文。默认白底，浅填充可以按内容省略；深色文字配浅填充。不要降低文本不透明度，也不要用浅色正文制造主次。

| 组件 | 默认样式 |
| --- | --- |
| 总标题 | 深蓝灰或主结构蓝，清楚简短，无标语 |
| 主要阶段标题与外框 | 标题使用阶段深色；外框深色、线宽1.5–2，可用对应浅填充 |
| 内部整体模块 | 名称有明确位置；需要外框时边框参考1.5，正文采用可实现的深色标签，不以无名算子替代 |
| 操作或对象节点 | 角色深色、线宽1.5–2，白底或角色浅填充，字号按测量确定 |
| 普通旁注与变量说明 | 深蓝灰，必要重点可用所属深色，保持与主结构相邻 |
| 附属详解 | 紧邻所属节点；标题和公式使用所属深色、正文深蓝灰；无框优先，必要时轻框线宽1 |
| 主流程数据线 | 深蓝灰或本图统一规定的阶段深色、实线、有箭头、线宽1.5–2 |
| 返回或反馈线 | 使用实际关系所属深色与清楚的方向，外围路由；必要时独立文字标明条件 |
| 解释关联 | 采用核心与周围详解结构时，独立附图关联通常用所属轻色、无箭头虚线，线宽约1；短旁注可省略，保持短而就近 |
| 来源 | 深蓝灰，字号20–22，不承担关键机制、接口或条件 |

当前节点绑定标签通常与节点边框共用 color。需要深蓝灰正文时使用独立说明对象；不要传未支持的 textColor 或强行把标签拆离绑定。字体、roughness 和描线风格以可读、轻手写为准，不放大粗糙度干扰公式或连线。

## 连接与阅读路线

流程线从源框明确侧边中点到目标框明确侧边中点，端点与边框保留一致小间隙。同行右中点至左中点，垂直下中点至上中点，反馈按真实方向选端口；错位用直角路线，分支共用明确干线，汇合回到目标中点。检查实际坐标、首末段、绑定与穿越，不仅看 focus=0。

流程优先连接实际入口、处理与出口节点，不因存在阶段容器就把所有箭头接到外框。只有整个模块确为传递对象时才连接其边界。需要解释关联线时使用 endArrowhead=none，先保持对象邻近，再规划短线；真实流程、依赖或反馈按已规划语义表达。包含靠命名分组，替代靠共同职责，不用带箭头的解释线伪造执行。路由无安全通道时腾出空间或使用合法 via，不用斜线穿文字来补偿。节点调整后重算受影响连接，检查邻区；原生任意拖动后的通道不保证保持此次设计。

先布置主要路径，再为各步骤预留邻近解释空间和并列支路，最后安排反馈通道。不同用途的线尽量不共用一段；交叉先局部重排与重算路线，不通过把解释搬远来解决。不要把每个框都连向每个解释。

连线按 authoring 的展示层级安排：总览先突出主要路径、关键分支和反馈，也保留串起主要区域的关键交接。资料支持的数据或产物传递、真实反馈使用实线箭头；仅共享组件或解释归属按相应语义表示，不画成执行先后。内部依赖留在局部机制，多处复用对象可就近命名引用以减少重复线，不能代替核心区域之间必要的联系。多个输入有真实共享关系时可用清楚干线与分支，不能把不同对象混成同一条线。标签只补充必要对象或条件，靠近对应线段且避开转角、正文和其他线；长字段列表移入旁注。修正拥挤优先检查层级、重复连接和标签必要性，再重排路线，不无限加大框体或缩字。

## 历史参考的解读

已认可的 Laya 成品提供可迁移原则：核心模块集中且有整体名称与必要嵌套，内部关系连续可辨，机制详解围绕所属部分展开，主次和文字比例清楚。参考这些组织方法，不复制它的模型事实、坐标、阶段数量或轮廓。外围布局与编号按任务需要选择，长引导线不替代清楚归属；向量、反馈和公式保持角色色。

参考的是这些层级、归属、测量和阅读方式。原稿的模型结构、阶段数量、字母数量、横纵位置、参数或训练过程不迁移到其他主题，也不要求新图复制其轮廓。具体历史按钮只在 legacy-laya 的条件下使用。

## 分区与实际工具

需要分组的外框声明 region，内部图元引用 regionId；空外框无 text，标题使用左上方独立文字，不用居中绑定标签遮挡内容。kind=main 标识主要区域，detail 标识详解，parentId 表示语义归属；主区域数量随内容决定。分区服务编辑和导航，不等于所有内容都装进一个大框，也不是每个步骤增加外框的理由；未分组步骤可直接使用节点，读取或聚焦时使用真实 ID。核心可跨多个区域：候选用 board_preview 检查，已保存核心用 board_render 的 elementIds 选择成员；不要把包含外围子详解的区域边界当成核心尺寸。工具参数区别见 tools。

parentId 表达语义归属，不代替空间邻近；详解可在父框内或紧邻其解释对象，真实包含由坐标与边界决定。缺少 region 的旧外框可按 tools 先声明再追加，不能用重建整板规避碰撞。整体移动可用 move_region；分区仍不是原生 frame。

根据 summary.bounds 和完整分页结果安排新内容，保留现有内容与安全间隔；向下追加时至少留140，其他方向按实际边界和走线留空间。不能把截断结果当成全图，不能为了布局移动未经授权的内容。

每批最多40个 items，自动生成绑定文字计入新增图元上限100。复杂整图可超过100图元，按区域预览；render 的 elementIds 最多100项。items 的箭头连接本批 alias，跨批 edits.connect 使用真实 ID，跨区长线的归属按聚焦范围决定。

新增图元可指定字号、边距和样式；既有图元可用 set_style、resize、move、move_region 及 reroute 局部修正。声明式路线按实际工具支持重算；不得杜撰字段，完整参数见 [tools.md](tools.md)。

导航来自 region 的 kind、order 与 lessonId，旧前缀只作兼容。分区成员随图元保存并支持撤销重做；导航只改变视口。后来新增的独立笔画不自动成为成员，在分区边界外时可能不在聚焦范围。

## 实际阅读核对

在常用窗口检查核心、全图和必要局部。暂不阅读外围详解时，核心自身能讲清关键对象、整体模块及关系，必要内部步骤没有被删成空泛标签；读核心无需滚动经过多个详解区才能找到下一环节。全图能辨认主次、共同职责与差异归属，不要求所有字同屏读清。采用核心与周围详解的结构时，核对附图是否视觉上小一级、能否沿关联找到具体解释对象，以及跨区域关键关系是否连续；不以每区各自清楚代替整体关系清楚。局部核对对象、对应说明、小图、公式、文字占比、颜色及连接；单区清楚不等于整体有效，补充后复看核心是否被撑散。

现有几何报告提供线索，不能证明逻辑正确或颜色符合语义；结合 authoring 的内容检查。改字、移动或调整样式均以用户范围为准，保留其他内容、原笔画与公式源码。
